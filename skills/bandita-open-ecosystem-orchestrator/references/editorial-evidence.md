# Evidencia editorial y catálogo

Usar esta referencia antes de investigar, añadir, corregir, excluir o promover una ficha.

## Jerarquía de fuentes

1. Repositorio oficial, sitio del proyecto, versión publicada o documentación de quien mantiene el software.
2. Forja de código mantenida por el proyecto y sus metadatos visibles.
3. Tienda oficial o distribución enlazada por el propio proyecto.
4. Comunidad, wiki, índice o tienda alternativa para descubrimiento, contexto y atribución; no para afirmar mantenimiento, licencia o compatibilidad sin fuente primaria.

## Registro mínimo

| Campo | Regla |
|---|---|
| Identificador | Usar un slug estable y evitar duplicar una ficha o cola existente. |
| Fuente canónica | Guardar URL, tipo de fuente y fecha de revisión. |
| Estado | Declarar activo, archivado, descontinuado o desconocido según la evidencia. |
| Licencia | Registrar SPDX solo si la fuente lo declara. |
| Actividad | Asociar una señal fechada; no convertir ausencia de señal en abandono. |
| Lanzamiento | Registrar versión y fecha solo desde un release o canal oficial observable. |
| Rol | Diferenciar cliente, servidor, extensión, índice, herramienta de descarga, utilidad local o puente. |
| Plataforma e idioma | Distinguir soporte nativo, web, complementario y no verificado; usar etiquetas BCP 47 cuando proceda. |
| Estado editorial | Usar `needs-review` hasta una decisión editorial; no describirlo como recomendado o aprobado. |

## Reglas de redacción

Escribir solo lo que la evidencia soporta. Separar capacidades técnicas declaradas de disponibilidad de contenido de terceros, autorización de uso y compatibilidad no probada. Atribuir a cada comunidad el papel de descubrimiento, contexto, verificación o antecedente editorial.

## Candidatos todo-en-uno

Clasificar una app multi-medio según su alcance declarado. No asumir que un cliente de anime también descarga, que una herramienta de descarga autoriza acceder a una fuente, ni que un servidor indexa contenido por sí mismo. Excluir o mantener fuera de la selección destacada los proyectos con señal insuficiente, archivo explícito o lanzamiento demasiado antiguo respecto al umbral acordado.

## Resultado esperado

Entregar fichas trazables, una lista separada de exclusiones o evidencia incompleta y una síntesis que no confunda recopilación con aprobación.
