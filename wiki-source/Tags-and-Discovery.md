# Tags and Discovery

> Tags help readers narrow a map. They do not certify availability, legality, security, compatibility or quality.

## Controlled theme tags

| Tag family | Allowed tags | Meaning |
|---|---|---|
| Medium | `reading`, `manga`, `anime`, `video`, `comics`, `graphic-novels`, `audio` | The entertainment format an entry directly addresses. |
| Resource type | `app`, `extension`, `source`, `directory`, `server`, `integration` | The technical role of the entry. |
| Platform | `android`, `desktop`, `web`, `ios`, `cross-platform` | A declared or observed platform, never an assumed one. |
| Evidence | `declared`, `observed`, `inferred`, `unconfirmed` | The calibration label defined in the [Evidence and Review Policy](Evidence-and-Review-Policy). |
| Editorial | `orientation`, `policy`, `workflow`, `template`, `attribution` | The role of a non-resource page in this Wiki. |

## Use

Add a compact **Tags** line near the beginning of each page. Link each tag to this reference and use only the controlled terms above. A page may use more than one medium, but should not add a tag until the cited source supports it. The Rethubs site search reads the same tags to narrow results; GitHub Wiki readers can use its built-in search or follow the linked tag reference.

## Discovery boundary

A community index can help locate a project, alias or archive, but it does not replace a project's canonical origin. The entry must preserve any relevant discovery credit, the date of review, and the direct source used to support each factual field.
