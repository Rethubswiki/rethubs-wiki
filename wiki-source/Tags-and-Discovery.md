# Tags and Discovery

> Tags help readers narrow the map. They do not certify availability, legality, security, compatibility, quality or endorsement.

## Controlled taxonomy

| Family | Allowed tags | Meaning |
|---|---|---|
| Medium | `reading`, `manga`, `anime`, `video`, `comics`, `graphic-novels`, `audio` | The entertainment format directly addressed by the record. |
| Resource type | `app`, `extension`, `source`, `directory`, `server`, `integration`, `store`, `guide`, `index` | The technical or editorial role. A page should choose the narrowest supported role. |
| Platform | `android`, `ios`, `macos`, `windows`, `linux`, `web`, `cross-platform` | A declared or observed platform; never an assumption based on a framework or a directory listing. |
| Relationship | `requires-host-app`, `requires-server`, `self-hosted`, `local-library` | A dependency boundary that needs a cited source. |
| Evidence | `declared`, `observed`, `inferred`, `unconfirmed` | The calibration label from [Evidence and Review Policy](Evidence-and-Review-Policy). |
| Editorial pages | `orientation`, `policy`, `workflow`, `template`, `attribution`, `changelog` | The role of a non-resource page. |

## Use tags as navigation, not verdicts

Add a compact **Tags** line near the beginning of each page. Link each controlled term to this reference. A page may have more than one medium or relationship tag, but only when the cited source supports it. The website search uses the same terms to narrow its document index; GitHub Wiki readers can use search or follow the linked routes.

## Discovery boundary

A community index, store or directory can help locate a project, alias or archive. It does not establish authorship, maintenance, compatibility, availability or the license of every linked item. Preserve any discovery credit, the review date and the canonical source used to support each factual field. See [Sources and Attribution](Sources-and-Attribution).
