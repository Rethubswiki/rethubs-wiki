# Compatibility Notes

## What this page can establish

Compatibility is documented **per project** and only from declared material: an official repository, release page, project documentation, or a maintainer statement. A directory listing, a community report, an old APK, or the absence of an issue report does not prove support.

| Field | What it records | What it does not establish |
|---|---|---|
| Project and canonical URL | The software being discussed | Trustworthiness of every download mirror |
| Platforms | Platforms explicitly named by the project | Support for all OS versions or device variants |
| Installation route | A source named by the maintainers | Safety of copied packages or third-party modifications |
| Resource relationship | Whether it is a client, extension family, server, index, or tracker | Interchangeability with another project |
| Last checked | Date of the supporting material review | A future maintenance commitment |

## Resource record

Each resource page should use the following block. Leave a field as `not declared` rather than extrapolating it from screenshots, discussion posts, or an adjacent project.

```text
Platforms: [declared platforms]
Minimum OS / runtime: [declared value or not declared]
Installation path: [canonical project path]
Extension or source family: [declared relationship or not applicable]
Known constraints: [maintainer-declared constraints]
Evidence checked: [YYYY-MM-DD]
```

## Low-resource use

The Wiki does not label hardware as universally compatible. When a project publishes requirements, they should be quoted or linked. When it does not, contributors may describe an **observed configuration** only when they identify it as observation, retain the date and build, and do not treat it as a guarantee for comparable devices.

For slow networks, prefer the project’s canonical release route and a small, clearly described download. Do not redirect visitors to copied installers, unsupported mirrors, or instructions that bypass a project’s own verification process.

## Review rule

Compatibility statements are evidence-bearing editorial records. An update that changes platform support, an installation path, or a constraint requires a source link and a dated review note before publication.
