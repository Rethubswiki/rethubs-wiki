# Source Routes

> This map explains **where to begin checking**. It does not certify every listing, availability claim, download, community statement or third-party service.

**Tags:** [orientation](Tags-and-Discovery#editorial-pages) · [directory](Tags-and-Discovery#resource-type) · [store](Tags-and-Discovery#resource-type) · [database](Tags-and-Discovery#resource-type) · [community](Tags-and-Discovery#resource-type)

## Read the source role before following a link

| Route | What it can help locate | What it cannot establish on its own |
|---|---|---|
| Store or repository | A package listing, release channel or discovery surface. | The safety, maintenance, licence or provenance of every listed item. |
| Directory or community index | A starting point, grouping or community-maintained route. | Canonical project facts, legal status, availability or a recommendation. |
| Database or calendar | Metadata, titles, dates, formats or release context. | A software download, project endorsement or regional availability. |
| Distribution or discussion surface | Context for a user's own research and policy review. | Permission to access, redistribute or use any material. |

## Stores and application repositories

| Source | Declared role in this map | Use with |
|---|---|---|
| [F-Droid](https://f-droid.org/) | Android software repository and client ecosystem. | A project’s own page, package metadata and current release information. |
| [IzzyOnDroid](https://apt.izzysoft.de/fdroid/) | Additional F-Droid-compatible repository route. | The repository listing and the canonical project source. |
| [OpenAPK](https://www.openapk.net/) | Web discovery surface for Android packages. | The developer or canonical repository rather than a thumbnail or mirror alone. |
| [Aurora Store](https://auroraoss.com/) | Independent client/project route. | Its own documentation and the individual application's official terms. |
| [Appteka](https://appteka.store/) | Alternative app-discovery catalogue. | A canonical project record; its entries are not imported automatically. |

## Directories and community maps

These sources can make a wide ecosystem easier to navigate. They remain **discovery sources**, so Rethubs uses them to locate candidates and then checks a project's own materials before an entry is presented as confirmed.

| Source | Scope stated in this map | Editorial boundary |
|---|---|---|
| [Wotaku Wiki](https://wotaku.wiki/) | Community reference for otaku-oriented tools and context. | No affiliation; a page is not treated as primary evidence. |
| [FMHY](https://fmhy.net/) | Broad community index and guide structure. | Its organization informs navigation only; Rethubs does not copy its catalogue. |
| [Miyomi](https://miyomi.app/) | Anime, manga and light-novel application/index context. | Kept distinct from the independent Rethubs editorial routes. |
| [EverythingMoe](https://everythingmoe.com/) | Anime and manga resource discovery. | Not a source of availability, permission or safety guarantees. |
| [The Index](https://theindex.moe/) | Library and collection patterns for exploration. | No commercial, product or service claims are reproduced. |
| [OneList](https://onelist.pro/) | Curated-list discovery route. | Individual listings need their own evidence. |
| [TheMoeWay](https://themoeway.com/) | Japanese-learning and cultural-resource context. | Include only after an active canonical route is confirmed. |

## Distribution and community context

Sources such as [Nyaa](https://nyaa.si/), [AnimeTosho](https://animetosho.org/), [r/Piracy](https://www.reddit.com/r/Piracy/) and [r/AnimePiracy](https://www.reddit.com/r/AnimePiracy/) may be named in community discussions. Rethubs does not list them as software stores, does not host or mirror files, and does not provide instructions to bypass access controls, copyright, regional rules or service terms. Treat them as context requiring independent policy and rights review.

## Verification route

1. Open the candidate’s canonical project or developer page.
2. Compare platform, licence, release and dependency claims.
3. Record the source role and last review date in the resource entry.
4. Use [Compatibility Notes](Compatibility-Notes) for platform boundaries and [Evidence and Review Policy](Evidence-and-Review-Policy) when the evidence is incomplete.
