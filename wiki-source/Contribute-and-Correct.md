# Contribute and Correct

> Contributions strengthen the map when they make a specific field more traceable.

**Tags:** [orientation](Tags-and-Discovery#editorial-pages) · [workflow](Tags-and-Discovery#editorial-pages)

## A useful proposal contains

| Field | Why it matters |
|---|---|
| Resource name and technical role | Prevents a client, source, server and directory from being collapsed into one label. |
| Canonical URL | Lets a reviewer trace the factual claim to the project or its documentation. |
| Exact field to add or correct | Keeps a proposal reviewable and avoids broad, unsupported rewrites. |
| Short explanation | Explains why the cited material supports the proposed record. |
| Discovery credit, if applicable | Preserves the community path that led to the candidate without replacing primary evidence. |

## Privacy and publication boundary

Do not include passwords, tokens, personal browsing data, copied installers or private correspondence. A proposal is a draft, not a publication. A reviewer may approve, request a correction or reject it according to the [Evidence and Review Policy](Evidence-and-Review-Policy). Only reviewed content merged into the source repository reaches the public Wiki.

## Correction path

For an existing entry, identify the page, exact line or field, authoritative URL and replacement language. The [Resource Entry Template](Resource-Template) explains the expected record. See [Community Participation](Community-Participation) for conduct and consent boundaries.
